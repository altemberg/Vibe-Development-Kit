# Vibe Development Kit (VDK)

VDK is an AI-first development methodology and repository blueprint for building modern software through a frontend-first, card-based, and human-orchestrated workflow.

The goal of VDK is to transform software development into a predictable process where product context, architecture, implementation, testing, and documentation evolve together.

---

# Core Principles

The official source of truth for all VDK principles is:

```txt
docs/constitution.md
```

Current principles:

* Frontend First
* Mock Data First
* Reuse Before Create
* English Only
* Naming Consistency
* Test Critical Flows
* Rule of Three
* Minimal Handoffs
* Card-Based Worktrees
* Human-Guided Development
* Framework First

---

# Development Lifecycle

VDK projects should follow this lifecycle:

```txt
Product Context
↓
Architecture
↓
ADRs
↓
Backlog
↓
Card
↓
Worktree
↓
Agent Pipeline
↓
Frontend
↓
Backend
↓
QA
↓
Review
↓

```

Code should be a consequence of decisions, not the starting point.

# Creating a New Project

## Step 1 — Create a New Repository

Create a new repository using the VDK template.

Example:

```bash
git clone <vdk-repository> .
```

---

## Step 2 — Define the Product

Create:

```txt
docs/product.md
```

Document:

* Product vision
* Purpose
* Target users
* Core modules
* Business rules
* Success metrics
* Long-term vision

This document becomes the primary source of business context for all agents.

---

## Step 3 — Define Architecture

Review or adapt:

```txt
docs/architecture.md
```

Document:

* Technology stack
* Feature structure
* Integration strategy
* Data access rules
* Multi-tenant rules
* AI architecture
* Communication architecture

---

## Step 4 — Generate ADRs

Create initial Architecture Decision Records.

Examples:

```txt
ADR-001 Feature-Based Architecture
ADR-002 Frontend-First Development
ADR-003 Webhook-First Integrations
ADR-004 Backend Platform
ADR-005 AI Provider Abstraction
```

---

## Step 5 — Generate Initial Backlog

Break the product into implementation cards.

Each card should be classified as:

```txt
small
medium
large
epic
```

And contain:

```yaml
id:
title:
description:
complexity:
status:
depends_on:
acceptance_criteria:
```

---

## Step 6 — Select the First Card

Recommended first cards:

```txt
Application Shell
Authentication
Dashboard Overview
```

---

## Step 7 — Create a Worktree

One card.

One branch.

One worktree.

Example:

```bash
git worktree add ../wt-card001-shell -b card001-shell
```

---

## Step 8 — Execute the Agent Pipeline

Depending on complexity:

### Small

```txt
PM
↓
Frontend
↓
Review
```

### Medium

```txt
PM
↓
Architect
↓
Frontend
↓
Review
```

### Large

```txt
PM
↓
Analyst
↓
Spec Writer
↓
Architect
↓
Frontend
↓
Backend
↓
QA
↓
Review
↓
Documenter
```

---

## Step 9 — Build Frontend First

Use:

* Realistic mock data
* Shared components
* Official framework patterns
* Official design system components

Backend implementation should only begin after frontend validation.

---

## Step 10 — Complete the Card

A card is complete when:

* Acceptance criteria are satisfied
* Critical flows are tested
* Documentation is updated
* Review is approved

# Repository Structure

```txt
agents/           Role-based agent personas
cards/            Work units and feature cards
artifacts/        Inputs and outputs generated by agents
docs/             Product, architecture, ADRs and documentation
templates/        Reusable templates
.claude/          Claude commands and worktree metadata
```

---

# Agent System

VDK uses role-based agents.

Current agents:

* Product Manager
* Card Analyst
* Spec Writer
* Software Architect
* Frontend Engineer
* Backend Engineer
* QA Engineer
* Code Reviewer
* Documenter

Agents are role-based, not technology-based.
